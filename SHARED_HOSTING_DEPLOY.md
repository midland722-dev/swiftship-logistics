# American Shipping & Logistics — Shared Hosting Deployment Guide

## Prerequisites

- PHP 7.4+ (8.x recommended)
- MySQL 5.7+ / MariaDB 10.3+
- Apache with mod_rewrite (or equivalent)
- cPanel / Plesk / DirectAdmin or similar shared hosting panel

## Step 1: Upload Files

Upload the entire project to your web root (e.g. `public_html/`).

**Recommended layout on shared hosting:**

```
public_html/
├── index.html          (generated by `npm run build`)
├── assets/             (generated by `npm run build`)
├── api/                (symlink or copy of `php/api/`)
├── process/            (symlink or copy of `php/process/`)
├── includes/           (symlink or copy of `php/includes/`)
├── config/             (symlink or copy of `php/config/`)
├── admin.php
├── contact.php
├── services.php
├── about.php
├── legal.php
├── privacy.php
├── terms.php
├── sustainability.php
├── careers.php
├── sitemap.php
└── .htaccess
```

**If you cannot place files in the web root**, keep the current structure and point your domain/subdomain to the project root.

## Step 2: Database

1. Create a MySQL database via your hosting panel.
2. Import `database/dbs.sql` via phpMyAdmin.
3. Run migrations in order:

```bash
# Option A: via browser (recommended on shared hosting)
# Visit each URL once:
https://www.yourdomain.com/../database/migrations/apply_0001.php
https://www.yourdomain.com/../database/migrations/apply_0002.php
...
https://www.yourdomain.com/../database/migrations/apply_0015.php

# Option B: via SSH CLI
php database/migrations/apply_0001.php
php database/migrations/apply_0002.php
...
php database/migrations/apply_0015.php
```

4. Run seeders:

```bash
php database/seeders/001_services.php
php database/seeders/002_company.php
php database/seeders/003_support_categories.php
```

## Step 3: Environment Configuration

Set environment variables in your hosting panel (cPanel → "Environment Variables" or `.htaccess`):

```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://www.yourdomain.com

DB_HOST=localhost
DB_NAME=your_db_name
DB_USER=your_db_user
DB_PASS=your_db_password
DB_CHARSET=utf8mb4
```

**cPanel `.htaccess` example:**
```apache
SetEnv APP_ENV production
SetEnv APP_DEBUG false
SetEnv APP_URL https://www.yourdomain.com
SetEnv DB_HOST localhost
SetEnv DB_NAME your_db_name
SetEnv DB_USER your_db_user
SetEnv DB_PASS your_db_password
```

## Step 4: PHP Configuration

Ensure these settings in `php.ini` or `.user.ini`:

```ini
session.cookie_httponly = 1
session.cookie_secure = 1
session.use_strict_mode = 1
upload_max_filesize = 10M
post_max_size = 10M
memory_limit = 128M
```

## Step 5: File Permissions

```bash
chmod 755 database/
chmod 755 database/migrations/
chmod 755 database/seeders/
chmod 644 database/dbs.sql
chmod 644 database/migrations/*.sql
chmod 644 database/migrations/apply_*.php
chmod 644 database/seeders/*.php
```

## Step 6: Security

1. **Delete or protect migration appliers** after running them:
   ```bash
   # Either delete:
   rm database/migrations/apply_*.php
   # Or restrict via .htaccess:
   # <Files "apply_*.php">
   #   Require ip 127.0.0.1
   # </Files>
   ```

2. **Set `APP_DEBUG=false`** in production.

3. **Enable HTTPS** and set `SESSION_COOKIE_SECURE=true`.

## Step 7: Verify

- Visit `https://www.yourdomain.com/` — React frontend should load.
- Visit `https://www.yourdomain.com/php/process/track_ajax.php?id=TEST` — should return JSON.
- Visit `https://www.yourdomain.com/php/api/auth.php` — should return 405.
- Visit `https://www.yourdomain.com/deprixa/` — login page should load.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| 500 Internal Server Error | Check `error_log` in cPanel. Common causes: PHP version mismatch, missing extensions (pdo_mysql), file permissions. |
| CORS errors | Ensure `APP_URL` is set correctly. Clear browser cache. |
| Database connection failed | Verify `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`. On shared hosting, `DB_HOST` is often a provided hostname, not `localhost`. |
| Stored procedure errors | Use the PHP applier (`apply_*.php`) instead of importing `.sql` directly. Shared hosting MySQL users often lack `CREATE ROUTINE` privileges. |
| Session not persisting | Ensure `session.save_path` is writable. Check cookie domain/path settings. |

## Post-Deployment

1. Create an admin user:
   ```sql
   INSERT INTO users (name, email, password, role, is_active, created_at)
   VALUES ('Admin', 'admin@yourdomain.com', '$2y$10$...', 'admin', 1, NOW());
   ```
   Generate the bcrypt hash with: `php -r "echo password_hash('YourPassword123', PASSWORD_DEFAULT), PHP_EOL;"`

2. Visit `/deprixa/` and log in.

3. Test tracking: `/track?id=TEST-001`

4. Test contact form: `/contact`
